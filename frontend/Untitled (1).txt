  RBAC Implementation Pattern

  Backend (auth.middleware.ts):
  protect()         → verifies JWT (Supabase or local JWT)
  authorize(roles)  → queries users table, checks profile.role against roles[]

  Frontend (consolidated-nav-legacy.tsx): Conditional render by user.role — 22 role blocks in renderNavigation()                                                                      
  
  Flutter (app_router.dart): _routeRoles map + getRoleRoute() redirect function. 9 roles not mapped in getRoleRoute() → all fall to /login.

  SECTION 12 — RECOMMENDED FLUTTER ARCHITECTURE             

  Keep (Proven Patterns)

  1. Riverpod everywhere — FutureProvider.family for parameterized queries, AsyncValue.when() for UI states                                                                           
  2. Repository pattern — one Repository class per feature domain, injected via Provider<Repository>
  3. GoRouter with redirect guards — role-based protection via _routeRoles map is correct                                                                                             
  4. Freezed models — type-safe, JSON-serializable. Continue for new models                                                                                                           
  5. ConsumerStatefulWidget for forms — correct pattern for dialogs with mutable state                                                                                                
  6. Offline POS — Drift SQLite queue works; extend to other modules                                                                                                                  
                                                                                                                                                                                      
  Add / Fix                                                                                                                                                                           
                                                                                                                                                                                      
  1. 9 new routes in app_router.dart + role_routes.dart                                                                                                                               
  2. New feature directories following the pattern:         
  lib/features/<feature>/                                                                                                                                                             
    data/repository.dart 
    domain/models.dart                                                                                                                                                                
    domain/providers.dart                                                                                                                                                             
    presentation/<feature>_screen.dart or <feature>_dashboard.dart
    presentation/sections/  ← for multi-tab dashboards                                                                                                                                
  3. Python repository — second Dio client (pythonDioProvider) already exists; add PythonReportsRepository, EmployeePortalRepository, GuestPortalRepository, BarcodeRepository        
  4. package_info_plus — for real app version in settings                                                                                                                             
  5. Adaptive layout — LayoutBuilder for desktop (sidebar) vs mobile (bottom nav) in new dashboards                                                                                   
  6. Real-time — confirm backend WebSocket support before implementing; fallback is polling via Timer.periodic in a Riverpod StreamProvider                                           
                                                                                                                                                                                      
  File Structure for New Dashboards                                                                                                                                                   
                                                                                                                                                                                      
  Each missing dashboard gets its own feature directory. The AdminScreen sections file pattern (single file with 80+ sections) does NOT scale — new dashboards use the DashboardShell 
  widget with proper tab routing.
