# Procurement Intelligence Reports Export Fix

## Problem
In Super Admin → Procurement Intelligence, clicking "Export All" or "Export KRA Format" shows "Failed to generate reports".

## Root Cause
The Python reports service is not running. The export functionality requires the Python service to generate PDF reports, but it's currently not accessible.

## Solution

### Start the Python Reports Service

The procurement intelligence reports (VAT Report and Procurement Intelligence) are generated by a Python service that must be running.

**Quick Start:**

```bash
cd python-services/reports
python app.py
```

The service will start on `http://localhost:5001`

### Verify It's Working

After starting the service, run this test:

```bash
node test-procurement-reports.js
```

You should see:
```
✅ Python service is running
✅ VAT Report generated successfully
✅ Procurement Intelligence Report generated successfully
```

### What the Python Service Does

The Python service (`python-services/reports/app.py`) handles:
- VAT Report generation (KRA format)
- Procurement Intelligence comprehensive reports
- GRNI (Goods Received Not Invoiced) analysis
- Supplier aging analysis
- Branded PDF generation with company logo

### Dependencies

Make sure Python dependencies are installed:

```bash
cd python-services/reports
pip install -r requirements.txt
```

Required packages:
- Flask
- ReportLab (PDF generation)
- psycopg2 (PostgreSQL connection)
- python-dotenv

### Configuration

The service uses these environment variables from `.env`:
- `PYTHON_SERVICE_URL` - Service URL (default: http://localhost:5001)
- `NEXT_PUBLIC_SUPABASE_URL` - Database connection
- `SUPABASE_SERVICE_ROLE_KEY` - Database authentication

### How It Works

1. User clicks "Export All" or "Export KRA Format"
2. Frontend calls `procurementAPI.exportProcurementIntelligencePDF()` or `procurementAPI.exportVATReportPDF()`
3. Request goes to Node.js backend `/api/reports/export`
4. Backend forwards to Python service `/api/reports/generate/branded-pdf`
5. Python service:
   - Fetches data from database
   - Generates branded PDF with company logo
   - Returns PDF file
6. Browser downloads the PDF

### Report Types Available

1. **VAT Report** (`vat_report`)
   - KRA-compliant format
   - Input VAT summary
   - Supplier invoice details
   - Withholding tax calculations

2. **Procurement Intelligence** (`procurement_intelligence`)
   - Comprehensive procurement overview
   - VAT summary
   - GRNI analysis
   - Supplier aging
   - Payment trends

### Troubleshooting

**If exports still fail after starting the service:**

1. Check service is running:
   ```bash
   curl http://localhost:5001/health
   ```

2. Check database connection in Python service logs

3. Verify supplier invoices exist in database

4. Check browser console for detailed error messages

**Common Issues:**

- **Port 5001 already in use**: Change `PYTHON_SERVICE_URL` in `.env`
- **Database connection failed**: Check Supabase credentials
- **No data in reports**: Add supplier invoices first
- **PDF generation error**: Check ReportLab installation

### Production Deployment

For production, the Python service should:
1. Run as a systemd service or Docker container
2. Use a production WSGI server (gunicorn)
3. Have proper logging and monitoring
4. Auto-restart on failure

Example systemd service:
```ini
[Unit]
Description=FG Reports Service
After=network.target

[Service]
Type=simple
User=www-data
WorkingDirectory=/path/to/python-services/reports
ExecStart=/usr/bin/python3 app.py
Restart=always

[Install]
WantedBy=multi-user.target
```
